# Echo-Back Conversion Unit — Plan (2026-10-09)

**Branch**: `feature/echo-back-convention`
**Doctrine**: Echo-back as component API convention (read-signals in, intent-callbacks out; parent owns state) — one of the three layered architectural laws (see `docs/DECISIONS.md` D7, `docs/plans/2026-09-25-node-graph-7c.md`).

## Goal

Convert every public component prop that takes `RwSignal<T>` (parent hands the
child a *write handle*) to the echo-back convention: `ReadSignal<T>` in,
intent-callbacks out. The child keeps an internal echo signal for its own
rendering and reactivity; user intents fire the existing `on_change`-family
callbacks; external value changes propagate inward via a sync effect.

**Every target component already has the correct callback props** — the
conversion moves state ownership only; no callback signatures change
(exceptions noted below).

## Design

### Shared helper (TDD, in `src/utils/`)

One util used by all 22 components instead of 22 hand-rolled effects:

```rust
/// Echo-back wiring: seed an internal signal from an optional external
/// read-signal and keep it synced (external → internal). Loop-guarded:
/// does not write when values are already equal.
pub fn echo_back<T>(external: Option<ReadSignal<T>>, internal: RwSignal<T>)
where T: Clone + PartialEq + Send + Sync + 'static;
```

Seeds `internal` from `external` (or leaves default), and when `Some`, installs
an `Effect` watching external → internal with equality guard. Component
commit paths become: `internal.set(new); if let Some(cb) = on_change { cb.call(new); }`
— they never touch external.

### Conversion rule (uniform)

1. Prop: `Option<RwSignal<T>>` → `Option<ReadSignal<T>>`. Required-into
   (`tabs.active`, `table.current_page`) → `Option<ReadSignal<T>>` with
   internal fallback + existing behavior when absent.
2. Body: `let internal = RwSignal::new(<seed>); echo_back(value, internal);`
   (default seeds: `false` / `String::new()` / `T::default()` per component —
   enumerate per contract).
3. Every previous write to the prop signal (`sig.set(..)`, `sig.update(..)`,
   `sig.set(...)` inside child-context consumers) → write `internal`; fire the
   existing callback on the same path (popover/accordion: new callback).
4. Context providers (`popover.rs:27`, `tabs.rs:34`) provide the **internal**
   signal; consumers unchanged.
5. Demo (`demo/src/**`) and doc examples updated: parent usage becomes
   `let (value, set_value) = signal(...);` + `value=Some(value)` (ReadSignal)
   + `on_change=Callback::new(set_value)`.

### Breaking-change policy

Pre-1.0 minor: allowed (CHANGELOG "Changed — breaking"). The only live
consumer (ur-frontend) is pinned to `main` @ 0.7.0 and updates with 0.8.0.

## Tests (TDD-first)

- Util: seed-with/seed-without external; sync propagates; equality guard
  prevents redundant writes; external None leaves internal untouched.
- Per component: callback fires on the user-action path (use each module's
  existing test style; pure-helper tests native, DOM behavior via the wasm
  harness where already established).
- API-level: `rg "RwSignal<" src/components/ | grep prop` returns only the
  sanctioned internal-signal lines (menu/notification/etc. whitelist) —
  enforced by a `tests/` grep-style test? No — enforced by review gate +
  documented whitelist here.
